# 시도 전용 후보(§15.317)

받는 쪽: mission-ops 실행 호스트. 무엇을 반입할지는 받는 쪽이 결정한다.

## 무엇이 생겼나
`adopt` 및 `assign` 에 `trialOnly: Set<String>` 매개변수가 추가되었다(기본값은 빈 집합, picasso `0ea44fa` 다음 커밋). 이 집합에 포함된 후보는 거절만 받아 가며, 관문을 통과해도 채택되거나 실행되지 않는다. 판정과 기록이 단일 호출 안에서 처리되므로 상태 변화로 인한 검사 틈이 발생하지 않는다.

## 쓰는 법
1. 잔여 파지 표시가 있고 다른 호스트 제한이 없는 기체를 `assign` 후보 목록에 넣고, 동시에 `trialOnly` 집합에도 넣는다.
2. 반환값이 `Unassigned` 일 때 다음과 같이 처리한다:
   - `Unassigned.refusals` 에 해당 기체가 있으면 이번 호출이 덧붙인 대장 줄(`remedySearches()` 를 부르기 전 길이로 자른 뒤)에서 조치를 읽는다. 열쇠(`proposal(기체, 작업 지시)`)로만 읽으면 앞선 시도가 세운 낡은 제안을 이번 답으로 보일 수 있다.
   - 조치가 없는 거절(자리·구역·결품)은 사슬 위반이 아니므로 표시 사유로 답한다.
   - `Unassigned.trialPassed` 에 해당 기체가 있으면 잔여 파지 표시 사유로 제외한 것처럼 응답한다.

## 지키는 것
- 시도 전용 후보는 통과해도 실행이 생성되지 않는다.
- 순위를 왜곡하지 않는다. 뒤에 있는 보통 후보가 통과하면 정상적으로 채택된다.
- 이미 실행이 선 작업 지시는 그 실행의 기체가 `trialOnly` 에 있으면 개정하지 않고 `Rejected` 로 답한다. 정착한 실행을 되살리는 개정도 실행이 서는 길이기 때문이다. 그 밖의 개정은 지금처럼 이 집합과 무관하다.
- 같은 기체가 순위에 두 번 있어도 한 번만 묻는다.

## 받는 쪽이 지킬 것
- 시도 전용 전환은 새 접수(그 작업 지시의 실행이 없을 때)에만 건다. 개정은 지금처럼 개정할 실행의 기체를 호스트가 판정한다.
- `trialPassed` 로 끝난 기체에 서 있는 앞선 제안은 승인 예외 대상에서 뺀다.

## 받는 쪽이 정할 것
- 호스트 응답의 구체적인 필드 구성.
- 승인 예외 처리 기준.
- 내부 감사 및 이력 기록 방식.
